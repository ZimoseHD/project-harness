# Issue Writing Aid

Use this optional outline to make a task understandable outside the conversation. Adapt the headings, order, and depth; existing project templates work too. Omit sections that add no useful information and replace illustrative placeholders with task facts.

```markdown
## 问题与目标

<现在的问题及期望结果>

## 改动范围

<涉及的行为或区域；必要时说明不做什么、兼容影响及迁移方式>

## 方案与决策

<实现思路、影响实施的重要选择与理由>

## 验收与验证

- <可观察结果及适用的验证方式>
```

Include source links or implementation steps only when they help. Describe uncertainty plainly. No protected-change declaration, decision status, memory-impact table, or exact formatting is required.
